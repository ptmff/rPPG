# Live rPPG: пульс по веб-камере

Прототип: веб-камера → лицо (YuNet) → два метода параллельно:

- **POS** (Wang et al., 2017): классический, без обучения. Работает по среднему цвету кожи лба и щёк.
- **RhythmMamba** (Zou et al., AAAI 2025): нейросеть с оригинальными весами авторов.
  Слой Mamba переписан на чистый PyTorch ([rppg/models/mamba_torch.py](rppg/models/mamba_torch.py)),
  поэтому модель работает на Mac без CUDA и без `mamba-ssm`.

## Запуск

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python live.py                 # веб-камера 0, оба метода
.venv/bin/python live.py --method pos    # только POS (torch не нужен)
.venv/bin/python live.py --weights weights/PURE_cross_RhythmMamba.pth
```

При первом запуске macOS спросит доступ к камере для терминала или VS Code.
Если окно не открылось, дай разрешение в «Системные настройки → Конфиденциальность → Камера».

В окне: зелёные рамки — участки кожи для POS, жёлтая — кроп лица для RhythmMamba.
Цвет числа показывает качество сигнала (SNR): зелёный — чистый, жёлтый — терпимо,
красный — скорее шум. Выход: `q` или `Esc`.

Первая оценка появляется через 6 с, дальше обновляется каждую секунду по окну 10 с.
RhythmMamba по умолчанию считает на GPU Apple (MPS): около 0.5 с на окно, на CPU около 1 с (`--device cpu`).

## Как получить нормальный результат

- Сиди неподвижно, лицо на весь кадр, свет ровный и спереди (не от монитора и не сбоку из окна).
- Если в статусе горит `AE/WB not locked`, камера сама меняет экспозицию и баланс белого.
  На macOS это обычное дело: встроенные камеры не дают их зафиксировать через OpenCV.
  Помогает ровный постоянный свет.
- `MOTION` в статусе означает, что голова двигалась: оценке в этот момент верить не стоит.

## Проверка точности

```bash
.venv/bin/python live.py --record rec.npz --log rec.csv   # запись начинается сразу, r - пауза
.venv/bin/python analyze.py rec.npz                       # разбор записи по секундам
```

Пока идёт запись, смотри на пульсоксиметр или часы, набирай число прямо в окне и жми Enter.
Значение сохранится с точным временем. `analyze.py` для каждого окна покажет оценку каждого
метода, три самых сильных пика спектра, fps, движение головы и частоту дыхания. В конце —
ошибку каждого метода относительно эталона и то, как часто истинный пульс вообще был среди
трёх пиков: если был, выбор пика можно исправить; если нет, сигнала в выходе метода просто нет.

Значения, записанные отдельно, можно передать так:
`analyze.py rec.npz --ref 121,110,91,98,91 --ref-start 5 --ref-step 10`.

Сравнить все веса на одной записи:
`analyze.py rec.npz --weights weights/*.pth`.

Офлайн по видеофайлу: `live.py --video clip.mp4 --headless --log out.csv`.

## Веса RhythmMamba (`weights/`)

| Файл | Обучен на | Когда брать |
|---|---|---|
| `MMPD_intra_RhythmMamba.pth` (по умолчанию) | MMPD: мобильные камеры, разная кожа, свет, движение | ближе всего к веб-камере |
| `PURE_cross_RhythmMamba.pth` | PURE: лаборатория, 30 кадров/с | чистые условия |
| `UBFC_cross_RhythmMamba.pth` | UBFC-rPPG | чистые условия |

## Тесты

```bash
.venv/bin/python -m pytest tests -q
```

Тесты синтетические, веб-камера для них не нужна.

## Структура

- [live.py](live.py): захват, буфер, отрисовка, лог
- [rppg/face.py](rppg/face.py): трекинг лица, участки кожи, кроп 128×128 как в rPPG-Toolbox
- [rppg/signal.py](rppg/signal.py): пересчёт на ровную частоту кадров, фильтры, частота пульса и SNR
- [rppg/methods/pos.py](rppg/methods/pos.py), [rppg/methods/rhythmmamba.py](rppg/methods/rhythmmamba.py): методы
- [rppg/models/](rppg/models/): модель RhythmMamba из репозитория авторов и Mamba на чистом PyTorch
